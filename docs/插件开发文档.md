# API Manager WASM 插件开发文档

> 文档版本：1.1
> 适用运行时：API Manager WASM Runtime
> 更新日期：2026-09-24

本文档说明如何为 API Manager 开发、打包、上传、启用和调用 WASM 插件。

## 1. 插件运行模型

API Manager 的 WASM 插件不是直接暴露 HTTP 端口的服务，而是由网关在匹配到 API 路由后调用：

```text
客户端请求
    │
    ▼
API Manager Gateway
    ├─ API 路由匹配
    ├─ API Key / JWT / HMAC 鉴权
    ├─ 请求参数校验
    ├─ 限流与配额
    ├─ 审计日志、指标、链路追踪
    │
    ▼
WASM Plugin
    │
    ▼
HTTP 响应
```

因此，**上传插件不会自动生成一个可访问的 URL**。必须再创建一个 API，将接口的“插件名称”设置为插件的 `name`，保存并发布后，客户端才能通过该 API 路由调用插件。

插件本身运行在 wazero 沙箱中，目前不提供：

- 宿主文件系统访问；
- 网络访问；
- 环境变量访问；
- PostgreSQL、Redis 等外部服务访问。

鉴权、限流、配额、审计、OpenTelemetry 和 Prometheus 指标由网关负责，插件不应自行实现这些控制逻辑。

## 2. 插件包目录结构

最小插件包需要三个文件（私钥不属于插件包）：

```text
my-plugin/
├── manifest.yaml
├── plugin.wasm
```

`entrypoint` 可以使用其他本地 `.wasm` 文件名，但必须位于同一插件包目录中。例如：

```text
my-plugin/
├── manifest.yaml
└── inventory.wasm
```

不允许使用目录穿越或绝对路径作为 `entrypoint`，例如以下写法会被拒绝：

```yaml
entrypoint: ../plugin.wasm
entrypoint: /tmp/plugin.wasm
```

## 3. manifest.yaml

### 3.1 完整示例

以下示例使用通用插件名，不依赖任何具体业务：

```yaml
id: example.api.inventory
name: inventory-demo
version: 1.0.0
api_version: v1
runtime: wasm
entrypoint: plugin.wasm
limits:
  timeout_ms: 3000
  memory_mb: 64
routes:
  - name: 服务状态
    method: GET
    path: /api/inventory-demo/v1/status
    auth_mode: api_key
  - name: 单品查询
    method: GET
    path: /api/inventory-demo/v1/items/{external_id}
    auth_mode: api_key
    example_path_params:
      external_id: example-id
    example_query:
      region: example-region
```

`routes` 是给控制台使用的能力声明，不会自动创建或发布 API。管理员仍需在“接口管理”确认配置并发布。路径必须使用最终的公开 API 路径，且与 API 的 method/path 精确匹配。

**升级已有插件：**旧版本 manifest 没有 `routes` 时仍可运行，但控制台只展示实际绑定的接口，不猜测新接口。如需显示新声明，请修改 manifest、提高 `version`、重新上传并启用新版本；相同 `name`+`version` 不允许重复上传。升级前先确保 WASM 模块真的实现了每条声明的接口。

### 3.2 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否 | 插件的稳定标识，建议使用反向域名格式。 |
| `name` | 是 | 插件名称。创建 API 时，接口的 `plugin` 字段必须填写此值。 |
| `version` | 是 | 插件版本。建议使用 SemVer，例如 `1.0.0`。 |
| `api_version` | 否 | 插件 ABI 或业务接口版本，推荐填写 `v1`。 |
| `runtime` | 是 | 当前必须为 `wasm`。 |
| `entrypoint` | 是 | 本地 `.wasm` 文件名，不能包含目录。 |
| `limits.timeout_ms` | 否 | 单次执行超时时间，单位为毫秒。未填写或为 `0` 时使用默认值 3000 毫秒。 |
| `limits.memory_mb` | 否 | WASM 最大线性内存，单位为 MiB。`0` 表示不额外设置该限制。 |
| `routes` | 否 | 插件支持的公开 API 声明；不会自动创建或发布 API。 |
| `routes[].name` | 否 | 控制台显示名称。 |
| `routes[].method` | 是 | `GET`、`POST`、`PUT`、`PATCH`、`DELETE`、`HEAD` 或 `OPTIONS`，必须大写。 |
| `routes[].path` | 是 | 最终公开路径，必须以 `/api/` 开头，不能包含 `//`、查询字符串或空白。 |
| `routes[].auth_mode` | 是 | `none`、`api_key`、`jwt` 或 `hmac`。 |
| `routes[].example_path_params` | 否 | 路径占位符的示例值，例如 `{external_id}` 对应 `external_id: example-id`。 |
| `routes[].example_query` | 否 | 控制台生成 curl 示例时使用的查询参数。 |

当前实现会拒绝以下情况：

- 缺少 `name`、`version`、`runtime` 或 `entrypoint`；
- `runtime` 不是 `wasm`；
- `entrypoint` 不是本地 `.wasm` 文件名；
- `timeout_ms` 或 `memory_mb` 为负数；
- 同一个插件名和版本的包已经存在；
- 插件包超过 `PLUGIN_MAX_BYTES` 限制。

## 4. WASM ABI

上传模块必须导出以下内容：

### 4.1 必须导出的内存

```text
memory
```

### 4.2 必须导出的函数

```text
alloc(size: i32) -> i32
handle(request_ptr: i32, request_len: i32) -> i64
```

ABI 约定如下：

1. 宿主调用 `alloc`，申请一段 WASM 线性内存；
2. 宿主把 JSON 请求写入返回的指针；
3. 宿主调用 `handle(request_ptr, request_len)`；
4. `handle` 返回一个 `i64`，高 32 位是响应指针，低 32 位是响应长度；
5. 宿主从 WASM 内存读取响应 JSON，并转换为 HTTP 响应。

返回值拆分方式：

```text
response_ptr = uint32(result >> 32)
response_len = uint32(result)
```

### 4.3 请求 JSON

宿主传给插件的请求结构如下：

```json
{
  "method": "GET",
  "path": "/api/example/v1/status",
  "query": {
    "region": ["US"]
  },
  "headers": {
    "accept": ["application/json"],
    "x-api-key": ["api-key-is-forwarded-but-should-not-be-logged"]
  },
  "body_base64": "",
  "api_id": "api_01JXXXXXXXXXXXXXXX"
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `method` | string | 原始 HTTP 方法。 |
| `path` | string | 原始请求路径。 |
| `query` | `map[string][]string` | 查询参数，多值参数会保留为数组。 |
| `headers` | `map[string][]string` | HTTP 请求头，多值请求头会保留为数组。敏感字段不得写入日志。 |
| `body_base64` | string | 请求体的 Base64 编码。宿主最多读取 1 MiB 请求体。 |
| `api_id` | string | 当前匹配到的 API 配置 ID。 |

### 4.4 响应 JSON

插件必须返回以下结构：

```json
{
  "status": 200,
  "headers": {
    "content-type": ["application/json"]
  },
  "body_base64": "eyJvayI6dHJ1ZX0="
}
```

其中 `body_base64` 解码后是实际 HTTP 响应体。例如上面的值解码后为：

```json
{"ok":true}
```

注意事项：

- `status` 为 `0` 时，宿主按 `200` 处理；
- `headers` 中的每个值都会添加到 HTTP 响应；
- `body_base64` 必须是合法 Base64，否则插件调用会失败；
- 业务错误建议通过 HTTP 状态码表达，例如 `400`、`404` 或 `500`，而不是让 ABI 调用失败；
- 插件执行失败时，网关会返回 `502`，并记录插件失败指标和日志。

## 5. Go 插件开发

当前项目推荐使用 Go 的 `wasip1/wasm` 目标编译插件，并使用 `//go:wasmexport` 导出 ABI 函数。

### 5.1 最小骨架

```go
package main

import (
    "encoding/base64"
    "encoding/json"
    "net/http"
    "unsafe"
)

type wasmRequest struct {
    Method  string              `json:"method"`
    Path    string              `json:"path"`
    Query   map[string][]string `json:"query"`
    Headers map[string][]string `json:"headers"`
    Body    string              `json:"body_base64"`
    APIID   string              `json:"api_id"`
}

type wasmResponse struct {
    Status  int                 `json:"status"`
    Headers map[string][]string `json:"headers"`
    Body    string              `json:"body_base64"`
}

var requestBuffer []byte
var responseBuffer []byte

//go:wasmexport alloc
func alloc(size uint32) uint32 {
    if size == 0 || size > 1<<20 {
        return 0
    }
    requestBuffer = make([]byte, size)
    return uint32(uintptr(unsafe.Pointer(&requestBuffer[0])))
}

//go:wasmexport handle
func handle(ptr uint32, length uint32) uint64 {
    if length == 0 || length > 1<<20 || len(requestBuffer) < int(length) ||
        ptr != uint32(uintptr(unsafe.Pointer(&requestBuffer[0]))) {
        return encodeResponse(http.StatusBadRequest, map[string]string{"error": "invalid request"})
    }

    var req wasmRequest
    if err := json.Unmarshal(requestBuffer[:length], &req); err != nil {
        return encodeResponse(http.StatusBadRequest, map[string]string{"error": "invalid request"})
    }

    return encodeResponse(http.StatusOK, map[string]any{
        "ok":     true,
        "method": req.Method,
        "path":   req.Path,
    })
}

func encodeResponse(status int, payload any) uint64 {
    body, err := json.Marshal(payload)
    if err != nil {
        body = []byte(`{"error":"encode response failed"}`)
        status = http.StatusInternalServerError
    }

    response := wasmResponse{
        Status: status,
        Headers: map[string][]string{
            "Content-Type": {"application/json"},
        },
        Body: base64.StdEncoding.EncodeToString(body),
    }
    encoded, _ := json.Marshal(response)
    responseBuffer = encoded
    ptr := uint32(uintptr(unsafe.Pointer(&responseBuffer[0])))
    return uint64(ptr)<<32 | uint64(len(responseBuffer))
}

func main() {}
```

### 5.2 编译

在插件源码目录执行：

```bash
GOOS=wasip1 GOARCH=wasm CGO_ENABLED=0 go build \
  -buildmode=c-shared \
  -trimpath \
  -o plugin.wasm \
  ./cmd/wasm-plugin
```

编译环境需要支持：

- `GOOS=wasip1`；
- `GOARCH=wasm`；
- `//go:wasmexport`；
- WASI reactor 模式下的 `_initialize` 生命周期。

项目内已有插件构建脚本时，优先使用项目脚本，因为它会使用项目验证过的编译参数输出 WASM 文件。当前 Go 插件构建脚本使用 `-buildmode=c-shared`，请不要改成普通宿主平台的 `c-shared` 目标。

### 5.3 其他语言

其他语言只要能生成满足 ABI 的 WASM 模块即可。需要确认：

- 导出名严格为 `memory`、`alloc`、`handle`；
- 函数参数和返回类型严格符合 ABI；
- 能生成 WASI Preview 1 模块，或不依赖无法提供的宿主导入；
- 不依赖文件、网络、环境变量等未开放能力。

## 6. 本地验证

### 6.1 检查模块导出

可以使用 `wasm-tools` 或其他 WASM 检查工具确认导出：

```bash
wasm-tools print plugin.wasm | grep -E 'memory|alloc|handle'
```

至少应看到：

```text
memory
alloc
handle
```

### 6.2 使用项目测试

在 API Manager 项目根目录执行：

```bash
go test ./...
```

如果插件包位于项目集成目录，还应执行对应的插件集成测试。测试至少应覆盖：

- 正常请求；
- 错误 JSON；
- 未知资源的 `404`；
- 请求体 Base64 解码；
- 查询参数；
- 响应头；
- 超时和过大输入；
- 插件模块缺少 ABI 导出时的加载失败。

## 7. 上传、启用和绑定 API

### 7.1 通过控制台

1. 打开 API Manager 控制台的“插件”页面；
2. 分别选择 `manifest.yaml`、`.wasm` 文件；
3. 点击“上传插件”；
4. 上传后在插件列表点击“启用”；
5. 在“接口与调用”区域为 manifest 已声明的路由点击“创建接口”，或手动进入“接口管理”；未声明路由的插件不会自动生成 status 建议；
6. 确保 API 的“插件名称”填写的是 manifest 中的 `name`；
7. 保存草稿并点击“发布”。

### 7.2 通过管理 API

以下命令使用占位变量，不要把真实管理员 Token 或 API Key 写入仓库：

```bash
export API_MANAGER=http://localhost:8080
export ADMIN_TOKEN='替换为管理员 Token'
```

上传插件：

```bash
curl -X POST "$API_MANAGER/admin/v1/plugins" \
  -H "X-Admin-Token: $ADMIN_TOKEN" \
  -F 'manifest=@manifest.yaml' \
  -F 'wasm=@plugin.wasm' \
```

响应中的 `id` 用于启用插件：

```bash
curl -X PUT "$API_MANAGER/admin/v1/plugins/<PLUGIN_ID>/status" \
  -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"enabled":true}'
```

创建一个绑定插件的 API：

```bash
curl -X POST "$API_MANAGER/admin/v1/apis" \
  -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Example status",
    "method": "GET",
    "path": "/api/example/v1/status",
    "auth_mode": "api_key",
    "plugin": "inventory-demo"
  }'
```

响应中的 API `id` 用于发布：

```bash
curl -X POST "$API_MANAGER/admin/v1/apis/<API_ID>/publish" \
  -H "X-Admin-Token: $ADMIN_TOKEN"
```

### 7.3 调用插件 API

API Manager 会在网关层完成 API Key 鉴权，然后将请求交给插件：

```bash
export API_KEY='替换为调用凭证中的 API Key'

curl "$API_MANAGER/api/example/v1/status" \
  -H "X-API-Key: $API_KEY"
```

如果 API 使用 JWT 或 HMAC，按照该 API 的鉴权配置调用即可。插件不需要、也不应该自行校验网关已经完成的 API Key。

## 8. 插件生命周期与版本规则

插件状态变化：

```text
上传（禁用） → 启用 → 绑定 API → 发布 API → 调用
                         │
                         └→ 下线 API / 禁用插件
```

规则：

- 上传后默认禁用；
- 同名插件最多启用一个版本；
- 启用插件时会编译并校验 WASM ABI；
- 禁用插件会从运行时注册表移除；
- 启用状态的插件不能直接删除，必须先禁用；控制台的“卸载”操作会自动先停用再删除；
- 卸载插件会删除插件包文件和托管记录，但不会自动删除已经创建的 API 路由；
- 删除插件会同时删除插件包文件；
- API 路由和插件是独立资源，删除插件不会自动删除 API 路由；
- API 路由引用不存在或未加载的插件时，调用会返回插件错误并记录日志。

## 9. 安全与性能建议

### 9.1 安全

- 不要在插件日志、响应体或错误信息中输出 API Key、JWT、Cookie 等敏感数据；
- 不要假设 WASM 能访问数据库、网络或文件系统；
- 插件只处理当前请求，不要把跨请求状态存放在全局变量中；
- 使用较小的 `timeout_ms` 和 `memory_mb`；
- 不要把管理员 Token 写入 manifest、源码或镜像；
- 业务权限应在 API Manager 的 RBAC、API 鉴权和路由配置中完成。

### 9.2 性能

- 尽量减少每次请求的 JSON 编解码和内存复制；
- 避免在插件中初始化大型数据集；
- 将静态配置编译进模块或通过请求输入传递；
- 将实时数据同步、数据库访问与 WASM 纯计算逻辑拆分为独立服务；
- 为每个接口配置合理的限流、超时和重试策略；
- 避免在 WASM 中实现不可控的长循环。

## 10. 常见问题

### 10.1 上传时报插件 manifest 错误

检查：

```yaml
runtime: wasm
entrypoint: plugin.wasm
name: your-plugin-name
version: 1.0.0
```

并确认 `plugin.wasm` 与 `entrypoint` 的文件名完全一致。

### 10.2 启用时报缺少 ABI 导出

确认模块导出了：

```text
memory
alloc(i32) -> i32
handle(i32, i32) -> i64
```

Go 项目需要使用 `//go:wasmexport alloc` 和 `//go:wasmexport handle`，而不是只声明普通 Go 函数。

### 10.3 API 返回 `404 api route not found`

通常是以下原因：

- API 尚未发布；
- 请求方法与配置不一致；
- 请求路径与配置不一致；
- 请求路径参数没有匹配；
- API Manager 当前运行的数据库不是创建接口时使用的数据库。

### 10.4 API 返回 `401` 或 `403`

这是网关鉴权或 RBAC 结果，不是 WASM ABI 错误。检查：

- API 的鉴权模式；
- `X-API-Key` 或 `Authorization` 请求头；
- 调用凭证是否已撤销或过期；
- 当前管理用户是否有对应权限。

### 10.5 API 返回 `502 plugin execution failed`

检查：

- WASM 是否在限制时间内返回；
- `handle` 是否返回合法的指针和长度；
- 响应是否是合法 JSON；
- `body_base64` 是否是合法 Base64；
- WASM 是否依赖网络、文件或未提供的 WASI 能力；
- 查看 API Manager 日志、Prometheus 插件失败指标和 OpenTelemetry 链路。

## 11. 发布前检查清单

- [ ] `manifest.yaml` 的 `runtime` 为 `wasm`；
- [ ] `name`、`version`、`entrypoint` 已填写；
- [ ] `entrypoint` 是包内 `.wasm` 文件名；
- [ ] 模块导出 `memory`、`alloc`、`handle`；
- [ ] `handle` 的返回值正确打包响应指针和长度；
- [ ] 所有响应的 `body_base64` 都可解码；
- [ ] 已测试正常响应和错误响应；
- [ ] 已设置超时和内存限制；
- [ ] 没有依赖网络、文件系统或环境变量；
- [ ] 已创建并发布 API 路由；
- [ ] API 的 `plugin` 值与 manifest 的 `name` 完全一致；
- [ ] 已配置 API 鉴权、限流和配额；
- [ ] 已使用调用凭证完成端到端测试；
- [ ] 没有把真实密钥写进源码、manifest、测试输出或文档。

## 插件库与数据写入

插件上传不需要签名文件或发布者公钥。上传接口接收 `manifest.yaml` 和 WASM 模块，服务端会校验清单、文件完整性和 WASM ABI。

本地插件库在控制台“插件”页面提供“加入插件库”和“安装”，仅展示结构完整且可通过 WASM 校验的本地插件包。`PLUGIN_LIBRARY_DIR` 决定目录；管理 API 是 `GET/POST /admin/v1/plugin-library` 和 `POST /admin/v1/plugin-library/install?name=...&version=...`。库不提供远程下载，安装后默认禁用。

manifest 可声明 `capabilities: [database_write]`，但默认会禁止启用该能力。`plugin_data` 表和主机侧写入接口仅为未来受控 JSON 数据写入预留，**目前没有 WASM host ABI，设置 `PLUGIN_DATABASE_WRITES_ENABLED=true` 也不能让插件实际写数据库**。
