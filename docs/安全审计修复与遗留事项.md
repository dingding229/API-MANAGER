# 安全审计修复与遗留事项（2026-09-24）

> 当前文档描述源码修复；**正在运行的容器不会因源码变更自动修复**。切换前请备份并规划维护窗口。不要把实际密钥、数据库备份或管理员 Token 放入项目目录。

## 已落实的防护

1. 进程拒绝空密钥、公开示例密钥、重复使用的密钥；Admin/JWT/API Key 加密必须相互独立。提供首次安装用 `scripts/init-secrets.py`（不会覆盖已有 `.env`）。
2. JWT 强制 `exp`、`iat`、issuer/audience（API JWT），限制最长期限为 24 小时；用户登录 Token 的 `sub` 必须与数据库用户 ID 一致。
3. HMAC 签名必须绑定 timestamp、nonce、method、URI 和 SHA-256 body；Redis 使用 SET NX + TTL 跨副本防重放，内存模式提供本机 nonce 缓存。
4. 已发布接口不能由仅有 `api.write` 的用户编辑；静态路由优先于模板；创建/导入和发布阶段阻止有歧义的模板路由。
5. 角色分配禁止非超级管理员自提权、授予高权限角色或变更角色权限；禁止禁用/移除最后一个活跃超级管理员。凭证列表与明文查看权限拆分。
6. 上游拒绝 URL userinfo；出口连接实际解析并验证全部 IP，仅允许运维预先批准的内网 origin；连接使用校验过的 IP，避免二次 DNS 解析；日志和 Trace 只记录安全 origin。
7. WASM 插件强制默认资源限制，限制请求、响应、头字段与状态码；插件 Registry 在处理请求时持读锁，启停不会立即关闭正在被调用的模块。
8. 管理/登录/初始化入口按真实 TCP 对端限流；Request ID 验证；未知路径和 HTTP method 不进入无限高基数指标。审计新增拒绝事件。Schema 和内存限流状态增加容量控制。
9. PostgreSQL 迁移加 session advisory lock；路由列表读取失败返回 503 而不是假 404。升级 Go 与依赖，Docker/Compose/Helm 默认非 root、限制端口、强制提供 Secret；Helm 默认单副本且拒绝误配置多副本。

## 现有容器切换前的必做步骤

1. 备份 PostgreSQL 与所有持久卷，并在隔离环境验证恢复；记录当前发布路由与插件状态。
2. 建立新的三个独立密钥、数据库密码、Grafana 密码；不要复用现有默认值。将新密钥存入有访问控制的 Secret 系统；`.env` 仅适合本机开发。
3. 如果旧凭证是用旧 Admin Token 回退加密的，先停网关，再使用旧值作为 `OLD_CREDENTIAL_ENCRYPTION_KEY`、新独立密钥作为 `CREDENTIAL_ENCRYPTION_KEY`，连接数据库执行 `go run ./cmd/rotate-credential-encryption`。工具使用单个数据库事务，无法解密任何一条记录时全部回滚。旧密钥随后必须清除。
4. 先在 PostgreSQL 内轮换数据库角色密码并更新 DSN；改变 Compose 中 `POSTGRES_PASSWORD` 本身不会修改已有数据卷中的角色口令。迁移已有 Docker 卷的写权限给运行 UID 65532；Kubernetes 卷需验证 `fsGroup` 生效。
5. 轮换现有 API Key、集成密钥和 Grafana 管理员口令；JWT Secret 轮换后旧登录会话将失效。将所有 HMAC 客户端升级到新的签名格式。
6. 根据实际环境允许的目标配置 `API_UPSTREAM_CREDENTIALS` / Helm NetworkPolicy `extraEgress`；内网访问不会因普通 API 编辑自动获准。
7. 重建并滚动验证 `/health/live`、`/health/ready`、路由鉴权、插件上传、密钥轮换和仪表盘。不要使用本次源码创建的新容器直接复用未经迁移的旧密钥数据库。

## 仍未完成或需要独立架构项目

- **多租户隔离**：目前是单租户，`tenant_admin` 为兼容保留的角色代码，界面标记“平台管理员（单租户）”。不可将其用作跨租户安全边界。
- **已发布配置快照/审批**：更新已发布资源现在要求 `api.publish`，但尚未实现不可变发布版本、草稿和审批；并发状态变更需要数据库层条件更新。
- **完整 PostgreSQL 错误传播与集成测试**：路由列表已可返回错误，但其他列表与 RBAC 查询仍有历史 Store 接口返回空列表的行为；需重构 Store 接口，增加真实 PostgreSQL 集成测试。
- **事务化审计**：登录/权限拒绝已记录，但业务写入与审计写入仍非同一事务；需要事务或 Outbox、retention/归档、失败告警。
- **多副本插件同步**：Helm 目前显式限制单副本；扩容前必须实现共享插件制品存储和实例间状态同步。
- **权限精细化**：`credential.reveal` 已从只读角色移除，但尚无 MFA/二次认证、按凭证归属限制或定期自动轮换。
- **现有本地文件**：历史发布私钥、集成环境文件及客户端密钥仍在项目目录（已被 ignore）；必须在确认用途及备份后迁移到受控 Secret 存储并评估轮换，不能由自动化脚本直接删除。
- **基础设施进一步收敛**：Compose 监控端口在新配置中只绑定 `127.0.0.1`，但容器内部 Loki/Tempo 仍未开启原生鉴权；Redis 与本地 PostgreSQL 仍是内部明文链路，生产应配置隔离网络、TLS/ACL 或托管服务。Alloy 的 Docker socket 挂载依然是高权限边界，应考虑日志代理或受限 socket 代理。
