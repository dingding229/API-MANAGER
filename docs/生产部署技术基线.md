# API Manager 生产技术基线（不包含反向代理实施）

本仓库的 `compose.yaml` 是**本地开发/验证**环境，不应直接上线。生产入口与 TLS 由运维自行部署；本文件仅定义应用、依赖、密钥、备份、监控和验收要求。**不要将本机的 `.env`、曾在聊天记录中显示的管理员 Token、`release-2026.key` 或游戏接口密钥复用到生产。**

## 1. 生产实例及依赖

- 使用独立的 `compose.production.yaml`，仅包含单副本 API；PostgreSQL、Redis、Prometheus、Alertmanager、日志/Trace 后端由运营方在**私有网络**提供。生产 Compose 不启动或暴露这些服务。
- 用经过审查的镜像**不可变 digest**设置 `API_MANAGER_IMAGE`，不要把 `latest` 当生产发布标识。宿主机绑定为 `127.0.0.1`；自行部署的代理只转发预期路由，**不要对公网暴露 `/metrics` 或监控系统**。管理页面与接口请额外做来源限制、速率限制和端到端 HTTPS（由反向代理设置 HSTS，应用不会信任未经配置的 `X-Forwarded-*`）；不用反向代理传来的未验证客户端 IP 做鉴权判定。
- `PRODUCTION_MODE=true` 强制 PostgreSQL（DSN `sslmode=verify-full`）、Redis TLS、独立 Metrics Token，拒绝内存降级。进程使用非 root、只读根文件系统、最低能力、进程/内存/CPU 限额。如启用 OpenTelemetry，必须配置私网 OTLP endpoint 并使用 TLS（`OTEL_EXPORTER_OTLP_INSECURE=false`）；自签 CA 需让容器/Pod 信任，且验证真实握手。Redis 服务端需开启 TLS 和密码/ACL（如需 ACL 用户名，设置 `PROD_REDIS_USERNAME`）；`REDIS_ADDR` 用证书中的主机名与端口，私有 CA 可使用 `REDIS_TLS_CA_FILE`（另行挂载 CA 文件）。
- 生产模式下管理员 Token **仅用于一次性 `/auth/v1/bootstrap` 初始化**，不能再作为 `/admin/*` 的万能凭证；后续使用具备权限的登录账号。若初始化账号丢失，需执行离线恢复流程，不通过长期持有的 Token 直接绕过 RBAC。当前尚无 MFA，限制管理入口可访问范围；高敏业务上线前需补齐 MFA/二次认证。
- 暂限单副本；多副本插件存储与加载广播尚未实现。不要将 `tenant_admin` 当作多租户隔离。Helm 部署也必须开启 `productionMode: true`、使用完整镜像 digest、预创建的 Secret（六个键：`ADMIN_TOKEN`、`USER_JWT_SECRET`、`CREDENTIAL_ENCRYPTION_KEY`、`POSTGRES_DSN`、`REDIS_PASSWORD`、`METRICS_TOKEN`）和持久卷；模板拒绝生产模式关闭持久化或禁用 Redis TLS。其 NetworkPolicy 生产默认拒绝所有入站；显式配置反向代理/Prometheus 来源 `networkPolicy.allowedIngress` 和获批目标 `networkPolicy.extraEgress`。

Helm `allowedIngress` 示例（替换为实际命名空间/Pod 标签；这只是连接许可，不部署或配置代理）：

```yaml
networkPolicy:
  allowedIngress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: gateway
          podSelector:
            matchLabels:
              app.kubernetes.io/name: my-reverse-proxy
      ports: [{ protocol: TCP, port: 8080 }]
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: monitoring
          podSelector:
            matchLabels:
              app.kubernetes.io/name: prometheus
      ports: [{ protocol: TCP, port: 8080 }]
```

## 2. 密钥与首次初始化

在**项目目录外且 Docker daemon 可访问的宿主机路径**选择全新的 `PROD_SECRETS_DIR`。Linux 示例使用 `/srv/private/api-manager`；如果 Docker daemon 运行在 Colima VM，须选已共享给 VM 的私有目录，不要直接用宿主机 `/tmp`。运行 `python3 scripts/init-production-secrets.py --dir /srv/private/api-manager` 生成四种独立密钥（程序不会打印内容）。再由管理员建立 `postgres_dsn` 和 `redis_password` 文件，不在仓库、命令参数或 shell 历史中放密码。PostgreSQL URL 需要 `sslmode=verify-full`；如使用私有 CA，把证书文件单独只读挂载并在 DSN 中配置 `sslrootcert`。Compose 可使用 `compose.production.private-ca.yaml` 覆盖层（设置 `PROD_CA_CERTS_DIR`，目录中放 `redis-ca.pem` 与 `postgres-ca.pem`，其中 `postgres_dsn` 的 `sslrootcert=/run/certs/postgres-ca.pem`）。Helm 可使用 `trustedCA.secretName` 挂载只读证书 Secret，`env.REDIS_TLS_CA_FILE=/etc/api-manager/ca/redis-ca.pem`，PostgreSQL DSN 设置对应 `sslrootcert`。证书目录需对非 root 容器可遍历（例如 `0755`），两个公有证书文件可读（例如 `0444`）；不要在该目录放入私钥或密码。设置 `PROD_CA_CERTS_DIR` 后预检也会检查证书文件。所有密钥都需要备份/轮换计划，特别是凭证加密密钥：**丢失会影响已发放密钥的再次查看**。

Compose 的 file-backed secrets 使用文件绑定挂载，不能可靠地通过 Compose `uid/gid/mode` 把宿主机 `0600` 文件重新映射给容器 UID 65532。因此将**目录**设置为仅管理员可进入（`0700`），六个**文件**在该私有目录中设置为 `0444`，供非 root 容器读取；主机上其他用户因无目录搜索权限不能打开它们。不要将这一做法套用到共享或可遍历目录。需要更强的文件所有权/动态轮换时，改用受控 Secret 平台/Kubernetes projected volume，不要把密钥写入环境变量或镜像。参考代码支持 `*_FILE` 和单值环境变量，但二者同时提供会拒绝启动。

启动示例（需要先备齐所有六个密钥文件和独立 PostgreSQL/Redis 服务；预检**不**测试真实 TLS 握手或依赖可用性）：

```bash
export API_MANAGER_IMAGE='registry.example/api-manager@sha256:<实际已验证的摘要>'
export PROD_SECRETS_DIR='/srv/private/api-manager'
export PROD_REDIS_ADDR='redis.internal.example:6380'
make production-check   # 本地输入校验：摘要、私有目录/文件权限、密钥独立性、TLS DSN
make production-up      # 校验通过后启动，不会部署反向代理
# 私有 CA 时：先 make production-check，另外设置 PROD_CA_CERTS_DIR，然后执行：
# docker compose --env-file /dev/null -f compose.production.yaml -f compose.production.private-ca.yaml config -q
# docker compose --env-file /dev/null -f compose.production.yaml -f compose.production.private-ca.yaml up -d
docker compose --env-file /dev/null -f compose.production.yaml ps
python3 scripts/verify-production.py --url http://127.0.0.1:8080 --secret-dir "$PROD_SECRETS_DIR"
```

验收脚本只读：检查就绪状态、匿名 Metrics 被拒、独立 Metrics Token 可用、管理员 Token 不可直接访问管理接口。**不会初始化账号**；首次初始化仍由管理员在安全入口手工执行。

## 3. 数据备份和恢复

定义并审批 RPO/RTO。此脚本**仅适用于 Docker Compose 卷**；Helm PVC/CSI 快照要按平台实现同等的数据库和插件制品一致性。应用写入暂停时，同一批次备份 PostgreSQL 与**两个**插件卷，避免数据库与制品版本不匹配。`scripts/backup-production.py` 使用 `PGSERVICEFILE` + `PGPASSFILE` 的 libpq 连接配置，不把数据库密码放在命令行；要求操作前停止 API/其他写入方。示例：

```bash
# 以下命令会造成 API 停机；按维护窗口执行。
docker compose --env-file /dev/null -f compose.production.yaml stop api-manager
export PGSERVICE='api-manager-prod'
export PGSERVICEFILE='/secure/private/postgresql/pg_service.conf'
export PGPASSFILE='/secure/private/postgresql/pgpass' # PostgreSQL 要求该文件权限为 0600
python3 scripts/backup-production.py \
  --output-dir '/secure/private/backups' \
  --plugin-volume api-manager-prod-plugin-data \
  --library-volume api-manager-prod-plugin-library \
  --tool-image 'registry.example/backup-tool@sha256:<经过审查的摘要>'
docker compose --env-file /dev/null -f compose.production.yaml up -d api-manager
```

脚本拒绝仍在运行的 API、未固定 digest 的备份工具和不安全的归档条目，生成 `database.dump`、`plugins.tar`、`plugin-library.tar`、`manifest.json` 与 `COMPLETE`；**结构校验不等于恢复成功**。将备份加密、异机保存、设置保留期；在隔离的 PostgreSQL 和新插件卷实际执行 `pg_restore`/解包、启动独立实例并跑读写冒烟测试后，才可宣称恢复演练通过。若要求更短 RPO，需要数据库 WAL 归档/PITR；同时给插件制品设计相同时间点的快照策略。

## 4. 监控和验收

- `configs/prometheus/prometheus.production.yml.example` 示范用私密 Token 抓取 `/metrics`；不要让 Prometheus 的 Token 文件落入仓库。
- `configs/alertmanager/alertmanager.production.yml.example` 示范真实 Webhook 接收方，需要运维另建私密 HTTPS URL 文件；开发环境的空接收方**不会通知任何人**。定期模拟宕机验证消息确实送达值班人。
- 控制台与 `/admin/*` 需要访问控制；Loki、Tempo 没有可直接依赖的内置终端用户认证，应仅部署在私有网络并按实际平台配置认证边界。生产 Compose 没有挂载 Docker socket；收集日志时使用权限受限的代理/平台日志系统。
- 在与生产一致的预发布环境完成 `make validate`、真实 PostgreSQL/Redis 集成测试、镜像扫描、权限与插件边界测试、压测、断网/数据库失效、备份恢复及回滚演练。记录镜像 digest、RPO/RTO、告警接收人、值班联系人和回滚步骤。

## 5. 仍未实现，不应误称“完全生产就绪”

非事务化审计（需要事务或 Outbox）、部分 Store 查询失败可能表现为空列表、不可变发布审批、MFA/凭证自动轮换、多副本插件同步、真正多租户隔离仍需独立工程。详见 `docs/安全审计修复与遗留事项.md`。若业务要求合规审计、高可用、多租户，这些是上线阻断项；单机单租户内部受控试运行可根据风险审批分阶段完成。
